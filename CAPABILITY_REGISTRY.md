# MographJailed Capability Registry 2.0

`system.describe` is the machine-readable contract that MJ consumers use to decide which Native operations and Standard Library modules are available and appropriate to call.

## Response

The response uses schema `MOGRAPHJAILED_CAPABILITY_REGISTRY_2` and includes:

- `registryVersion`: registry contract version (`2`)
- `protocolVersion`: MJ Native transport protocol version
- `cliVersion`: running Native runtime version
- `standardLibrary`: Standard Library 1.0 module/policy descriptor
- `operations`: descriptor keyed by public operation name

### Standard Library descriptor

`standardLibrary` is additive to Registry 2.0 and currently reports:

- library version
- local-only/network policy
- absence of raw shell and arbitrary SQL APIs
- `LocalFS`
- `NativeDB`
- `MediaProbe`
- `ImageKit`
- `FrameKit` candidate state and target-Mac qualification requirement

NativeDB availability is based on a static in-memory SQLite runtime probe. JSON and FTS5 feature flags are also tested in `:memory:`; no persistent database is created by `system.describe`.

## Operation descriptor

Each operation exposes:

- `available`: whether the operation can currently execute its normal path
- `state`: `AVAILABLE` or `UNAVAILABLE` for public operations
- `cost`: expected execution-cost class
- `mutation`: mutation scope
- `authority`: semantic strength of the result
- `interactiveSafe`: whether the operation belongs in latency-sensitive UI paths by default
- `networkSensitive`: whether network-backed targets can materially affect execution
- `executionScope`: `LOCAL_ONLY` where the runtime itself blocks non-local storage, otherwise `EXPLICIT_PATH_OR_NONE`
- `requires.all`: capabilities that must all be present
- `requires.anyOf`: alternative capability groups where one member is sufficient
- `optionalCapabilities`: capabilities that improve an operation without being required for its basic path

## Consumer rule

MJ applications should prefer the registry over hardcoded assumptions. Registry data describes capability and safety; it does not make product decisions.

Examples:

- MJ_Organize may use `storage.preflight` to understand a caller-supplied path, but Native does not decide where an asset should be moved.
- MJ_AE_Looper may call `media.timing` only when available and when the asset is local; the operation is explicitly not interactive-safe.
- `file.hash` remains inappropriate as an automatic UI action on a large asset because cost grows with size and storage latency.

## Authority values

Existing values remain valid. Standard Library 1.0 adds:

- `NORMALIZED_NATIVE_MEDIA`: a normalized MJ response derived from labeled native media facts with fail-closed parser validation
- `NATIVE_FRAME_DERIVATIVE`: a new local PNG derivative generated by the fixed native FrameKit adapter

This is stronger than advisory Spotlight metadata but is not a claim that every field is sample-enumerated. `media.timing` explicitly marks nominal frame rate as advisory-nominal and reports that its full sample table was not enumerated.

## Mutation values

- `NONE`
- `TEMP_CREATE`
- `TEMP_DELETE`
- `INTERNAL_TEMP`
- `DERIVATIVE_CREATE`

Source mutation remains absent from the public API.

## Standard Library 1.0: `media.timing`

`media.timing` retains its Protocol v1 command name but is no longer a placeholder when the required native capabilities are present.

Contract characteristics:

```text
cost             BOUNDED_MEDIA_PROBE
mutation         NONE
authority        NORMALIZED_NATIVE_MEDIA
interactiveSafe  false
networkSensitive true
executionScope   LOCAL_ONLY
requires.all     avmediainfo, awk, df, uname
```

The adapter:

1. validates the source as a readable regular file;
2. positively classifies the backing filesystem as local;
3. runs `avmediainfo --brief` as an analysis-success gate;
4. captures only the pre-`Sample Information` header from `--samples --mediatype video`;
5. enforces a 256-line output ceiling;
6. parses only labeled fields with numeric validation;
7. fails closed on shape drift.

It does not enumerate the sample table in the default operation.

## Stability

Registry additions are additive where possible. A change that reinterprets an existing field or operation in a breaking way requires an explicit compatibility decision rather than silent drift.

Capability collections remain true JSON arrays with one capability per string element under production zsh and QA bash.


## Standard Library 1.0: `media.frame` candidate

0.3.0-dev.2 adds one public operation while preserving Protocol v1 transport semantics.

```text
cost             FRAME_DECODE
mutation         DERIVATIVE_CREATE
authority        NATIVE_FRAME_DERIVATIVE
interactiveSafe  false
networkSensitive true
executionScope   LOCAL_ONLY
requires.all     avmediainfo, osascript, jq, sips, awk, df, mktemp, mv, rm, stat, uname
```

Contract summary:

1. source and output parent must be positively identified local filesystems;
2. source must be a readable regular file with a decodable video track;
3. requested time must be non-negative and strictly before media duration;
4. output must be a new `.png`; overwrite is refused;
5. maximum dimension is bounded 64–4096 pixels, default 2048;
6. AVFoundation preferred-track transform is applied;
7. time tolerance before/after is zero;
8. response preserves requested and actual generated time independently;
9. source identity is compared before/after decode;
10. staged output is positively identified by ImageKit before non-overwriting publish.

`available:true` in this candidate describes machine capability, not promotion status. Product releases should continue pinning the qualified dev.1 baseline until the dev.2 Mac/AE qualification gates pass.
